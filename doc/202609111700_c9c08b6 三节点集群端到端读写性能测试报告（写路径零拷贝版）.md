# taihu 三节点集群端到端读写性能测试报告（128.11/12/13 × 3 盘，写路径零拷贝版）

日期：2026-09-11
基线 commit：`c9c08b6`（写路径零拷贝：共享内存 Put 帧分段直写设备，消除 bufpool 汇集拷贝）+ `ae5d667`（server 启动参数重构：-listen 多 IP、端口自动分配、shm socket 固定 /dev/<实例名>、Node 标识取 hostname）
部署二进制（三节点一致）：`taihu-server.direct`（md5 39a01b46）/ `taihu-rpc-bench.direct`（md5 6606b5a5），arm64

## 1. 测试目标

三节点 × 3 盘位（9 实例）taihu 集群端到端读写性能，采集：
物理机 CPU（mpstat）、客户端/服务端进程 CPU（pidstat）、网络带宽（/proc/net/dev 差分）、
客户端与服务端 pprof、客户端带宽与延迟（bench 输出）。对比写路径零拷贝改造前后。

## 2. 测试环境

| 项 | 值 |
|----|----|
| 节点 | 100.71.128.11（hostname XCKP04）/ .12（XCKP05）/ .13（XCKP06），各 96 核 aarch64 |
| 实例 | 每节点 3 × taihu-server（-listen 多 IP、端口自动分配 50000-51000、shm socket /dev/nXX-nvmeN） |
| 数据设备 | 每节点 nvme1n1/nvme2n1/nvme3n1 |
| 元数据 | pebble（/tmp/taihu-db/nvme{1,2,3}）+ TiKV 索引（PD 三节点 2379） |
| 压测 | taihu-rpc-bench 集群模式（-node <hostname>/-tikv-pd），客户端放各节点本机 |
| 对象 | 4 MiB × 40000/节点（各节点独立前缀 p4m-cl4a/b/c，避免覆盖写） |
| 线程 | 32/节点 |

## 3. 测试方法

- 三节点**并行**执行（各写/读本地盘，独立前缀互不干扰）；`-node` 用 hostname（新 server 注册 Node=hostname，rpccluster 本地实例按 Node 匹配）
- 写：`-mode write -node <hostname> -keys-prefix p4m-cl4{a|b|c} -size 4194304 -count 40000 -threads 32 -latency -cpuprofile`
- 读：`-mode read` 同批 key（各读自己前缀）
- 采样：mpstat -P ALL、pidstat、/proc/net/dev 差分、pprof（客户端 -cpuprofile / 服务端 pprof 端口）

## 8. 网络带宽（/proc/net/dev 差分）

| 阶段 | 节点 | 数据面 | 说明 |
|------|------|--------|------|
| 写 | 全部 | **0** | 数据走 shm 本地；bond0 仅 MB 级（TiKV 索引 gRPC） |
| 读 | 全部 | **0** | 128.11 bond0 读窗口 +63MB ≈ TiKV 索引查询（40000 次），非数据面 |

**数据面零网络带宽**：同机实例走 shmipc（注册 ShmAddr=/dev/nXX-nvmeN），客户端 DialShm 本地。

## 9. pprof 热点（128.11 代表性）

### 写服务端
| 热点 | 占比 | 说明 |
|------|------|------|
| syscall.Syscall6 | 50.6% | O_DIRECT 写（io_submit/io_getevents）；**memmove 0**（旧版 71.7%） |

### 读客户端
take=40000 copy=0（共享内存零拷贝）。

## 10. 瓶颈分析与结论

1. **写 21.6 GiB/s、读 51.5 GiB/s**，零拷贝 take 100%。
2. **写路径零拷贝生效**：服务端写 memmove 71.7%→0，服务端写进程 CPU 30-36%→12-16%（减半）；写带宽不变（单盘写极限 2.5 GiB/s×9 盘）。
3. 读服务端进程 CPU 31-45%（较此前 13-16% 高，整机仍 1.5-1.8% 非瓶颈），可能含 pprof 窗口内瞬时负载；读路径 memmove 保持 0。
4. 数据面零网络（shm），TiKV 仅元数据。
5. 注意：新 server Node=hostname，rpccluster 客户端 `-node` 须传 hostname 才命中本地实例（IP 不匹配会数据分布混乱）。

## 11. 测试还原

```bash
# server（每节点 3 实例）
taihu-server -listen 100.71.128.1X -db /tmp/taihu-db/nvme{i} -dev /dev/nvme{i}n1 \
  -name n1X-nvme{i} -tikv-pd 100.71.128.11:2379,...
# 写（三节点并行，-node 用 hostname，独立前缀）
taihu-rpc-bench -mode write -node <hostname> -tikv-pd ... -size 4194304 -count 40000 -threads 32 -keys-prefix p4m-cl4{a|b|c} -latency -cpuprofile
# 读
taihu-rpc-bench -mode read -node <hostname> -tikv-pd ... -size 4194304 -count 40000 -threads 32 -keys-prefix p4m-cl4{a|b|c} -latency -cpuprofile
# 采样
mpstat -P ALL 1 / pidstat 1 / /proc/net/dev 差分 / server pprof（nvme1 端口 50005/50003）
```
