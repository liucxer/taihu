# taihu 三节点集群端到端读写性能测试报告（128.11/12/13 × 3 盘，客户端零拷贝写 API 版）

日期：2026-09-11
基线 commit：`4f4e4ff`（客户端零拷贝写 API：PutWriter.Reserve 直写共享内存，消除客户端写 memmove）+ `c9c08b6`（服务端写分段直写）+ `ae5d667`（server -listen 多 IP）
部署二进制（三节点一致）：`taihu server.direct`（md5 39a01b46）/ `taihu bench cluster.direct`（md5 9d645c07），arm64

## 1. 测试目标

三节点 × 3 盘位（9 实例）taihu 集群端到端读写性能，采集：
物理机 CPU（mpstat）、客户端/服务端进程 CPU（pidstat）、网络带宽（/proc/net/dev 差分）、
客户端与服务端 pprof、客户端带宽与延迟（bench 输出）。

## 2. 测试环境

| 项 | 值 |
|----|----|
| 节点 | 100.71.128.11（hostname XCKP04）/ .12（XCKP05）/ .13（XCKP06），各 96 核 aarch64 |
| 实例 | 每节点 3 × taihu server（-listen 多 IP、端口自动分配、shm socket /dev/nXX-nvmeN） |
| 数据设备 | 每节点 nvme1n1/nvme2n1/nvme3n1 |
| 元数据 | pebble（/tmp/taihu-db/nvme{1,2,3}）+ TiKV 索引（PD 三节点 2379） |
| 压测 | taihu bench cluster 集群模式（-node <hostname>），客户端放各节点本机 |
| 对象 | 4 MiB × 40000/节点（独立前缀 p4m-cl5a/b/c），线程 32/节点 |

> 注：集群模式客户端（rpccluster.Storage）暂未接入零拷贝写（NewPut 仅 rpcclient.Storage 直连支持），
> 本测集群写仍走普通 Put（客户端 memmove 保留）；单实例零拷贝写效果见 shm-bench 单独验证（memmove 86.87%→0）。

## 9. 瓶颈分析与结论

1. **写 21.6 GiB/s、读 51.7 GiB/s**，零拷贝 take 100%。
2. **服务端读写 memmove 均为 0**（写=c9c08b6 分段直写，读=fca9658 直读共享内存）；服务端进程 CPU 27-41%（写）/32-41%（读），整机 ≤2.7% 非瓶颈。
3. **集群写客户端 memmove 84.86% 仍在**：rpccluster 客户端未接入零拷贝写（4f4e4ff 仅 rpcclient.Storage 直连支持）；单实例 shm-bench 零拷贝写已验证 memmove→0。**下一步**：rpccluster.Storage 透传 NewPut 到内部 rpcclient.Storage。
4. 数据面零网络（shm），TiKV 仅元数据。
5. 注意：`-node` 须传 hostname（新 server Node=hostname）。

## 10. 测试还原

```bash
# server（每节点 3 实例）
taihu server -listen 100.71.128.1X -db /tmp/taihu-db/nvme{i} -dev /dev/nvme{i}n1 -name n1X-nvme{i} -tikv-pd ...
# 写/读（三节点并行，-node <hostname>，独立前缀）
taihu bench cluster -mode write|read -node <hostname> -tikv-pd ... -size 4194304 -count 40000 -threads 32 -keys-prefix p4m-cl5{a|b|c} -latency -cpuprofile
# 单实例零拷贝写验证（shm-bench）
taihu-shm-bench -shm /dev/n1X-nvme1 -mode write -size 4194304 -count N -threads T -keys-prefix zc -zero-copy-write
```
