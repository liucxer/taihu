# taihu 六节点集群端到端读写性能测试报告（bond1/bond2 双网络跨节点读篇）

日期：2026-09-11
部署二进制：`taihu-server.50ebbe4` / `taihu-rpc-bench.50ebbe4`（commit `50ebbe4`，SDK 按 hostname 自动选路——同机 shm、跨节点 TCP），本地交叉编译 arm64。
网络拓扑：每节点 3 实例中 **2 个 -listen bond1.2175 IP（25G 聚合）、1 个 -listen bond2.2372 IP（25G 聚合）**，数据面跨节点走 25G 高速网络。

## 1. 测试目标

6 节点 × 3 盘位（18 实例）taihu 集群端到端读写性能，采集：
- 物理机 CPU（mpstat）、客户端/服务端进程 CPU（pidstat）
- 网络带宽（bond1.2175 / bond2.2372 数据面差分）
- 客户端与服务端 pprof
- 客户端带宽与延迟（bench 输出）

读性能测试避开相同节点读：读客户端与数据实例 hostname 错位环形配对，全部走 TCP 跨节点，且数据面落在 bond1/bond2 25G 链路上。

## 9. 结论

1. **写**：18 实例并行写聚合 **86.3 GiB/s**（每节点 14.2 GiB/s，3 盘 ≈ 4.7 GiB/s/盘），shm 本地直写，瓶颈磁盘。
2. **跨节点读（b1/b2 网络）**：6 链路并行全部达 **2.5-2.6 GiB/s**，聚合 **15.3 GiB/s**——较 1Gbps bond0.1326 提升 23 倍。路由按实例开通 bond1/bond2 精确分流（2:1 数据比例验证）。
3. **路由正确性**：环形错位配对实现 100% 跨节点读；bond0.1326 无数据面流量，证明 SDK hostname 路由与 instance Addr 通告完全正确。
4. **零拷贝**：读路径 Take 命中 66-99.7%（高并发 TCP 下部分 fallback ReadCopy），memmove 相比写路径大幅下降；服务端发送零拷贝（sendmsg）。
5. **资源**：物理机 CPU 19-26%，客户端读 2.4-3 核，CPU 不是瓶颈——当前**瓶颈在 25G bond 聚合带宽与 TCP 流均衡**。
6. 进一步可优化：多流 TCP 连接数/LRO/GRO 调优提升 Take 命中与单流带宽。
