# taihu 集群读写性能测试报告（128.11/12/13 三节点九盘，共享内存路径）

日期：2026-09-11
基线 commit：`083c4d3` + 本地 `-shm` 支持（未提交改动）

## 1. 测试目标

1. 测得集群（三节点九盘）最大读/写带宽。
2. 确认数据访问是否**都通过共享内存（shmipc）访问本地盘**，还是存在**节点间 TCP 通信**。

## 2. 部署与改造

### 2.1 拓扑

| 节点 | 实例 | 盘 | 端口 | -shm |
|------|------|----|------|------|
| 100.71.128.11 | n11-nvme1/2/3 | nvme1/2/3 | :50051-53 | /tmp/taihu-shm/n11-nvme*.sock |
| 100.71.128.12 | n12-nvme1/2/3 | nvme1/2/3 | :50051-53 | /tmp/taihu-shm/n12-nvme*.sock |
| 100.71.128.13 | n13-nvme1/2/3 | nvme1/2/3 | :50051-53 | /tmp/taihu-shm/n13-nvme*.sock |

- TiKV/PD 三节点 `100.71.128.11:2379,100.71.128.12:2379,100.71.128.13:2379`
- **本次改动**：9 server 启动加 `-shm <unix socket>`（shmipc 共享内存 IPC 通道，与 TCP 并行）；`InstanceInfo` 增加 `ShmAddr` 字段并上报；`rpccluster.Storage.clientFor` 对**同 node 实例优先 `DialShm`（共享内存）**、跨节点 `DialPool`（TCP）。
- 压测工具 `taihu bench cluster` 新增集群模式（`-node` + `-tikv-pd` 走 `rpccluster`）。

### 2.2 访问路径判定方法

本地 shm 访问（unix socket）不产生到 127.0.0.1:5005x 的 **TCP 连接**；跨节点访问必然建立 TCP。测试期间用 `ss -ltnp` 观察 TCP 连接到 server，佐证本地访问走 shm、无网络 TCP。

## 3. 测试结果

### 3.1 单机本地 shm 访问本地盘（128.12 本机客户端，4MiB 对象）

| 模式 | threads | ops/s | 带宽 | p50 | p90 | p99 |
|------|---------|-------|------|-----|-----|-----|
| 写 | 1 | 256.7 | 1026.86 MiB/s | 3.42ms | 5.13ms | 6.30ms |
| 写 | 16 | 1592.1 | 6368.22 MiB/s | 8.25ms | 15.02ms | 29.88ms |
| 写 | **32** | **1740.6** | **6962.53 MiB/s** | 16.65ms | 25.16ms | 43.34ms |
| 读 | 32 | 3402.0 | 13607.88 MiB/s | 6.61ms | 10.79ms | 55.20ms |
| 读 | 32(复) | 2865.3 | 11461.20 MiB/s | - | - | - |

- 写 32 线程 ≈ **6.96 GiB/s**（本地三盘汇聚，每盘约 2.3 GiB/s，接近各盘写极限）；
- 读 32 线程 ≈ **13.6 GiB/s**（三盘读并发，读带宽显著高于写）。

**64 线程压测失败**：shmipc 会话过载，出现大量
`client session receive fallback data` + `session is unhealthy`，即共享内存环形缓冲在高并发大对象下不足，回退/失败。32 线程为稳定最优并发。

### 3.2 集群汇聚带宽（三节点并行，各写/读本地盘）

| 模式 | 128.11 | 128.12 | 128.13 | 汇聚 |
|------|--------|--------|--------|------|
| 写 32T | 6515.21 | 6431.96 | 6719.01 MiB/s | **≈ 19.7 GiB/s** |
| 读 32T | 13836.03 | 12487.79 | 10057.25 MiB/s | **≈ 36.4 GiB/s** |

- 每节点独立写本地三盘 ≈ 6.5-6.7 GiB/s，节点间**互不干扰**（各自走本地 shm）；
- 集群写汇聚 ≈ **19.7 GiB/s**，读汇聚 ≈ **36.4 GiB/s**（资源可随节点数线性扩展）。

### 3.3 访问路径判定：共享内存 vs 节点间通信

**结论：集群本地优先场景下，数据访问全部通过共享内存（shmipc unix socket）命中本地盘，无节点间 TCP；仅跨节点读才走 TCP 网络。**

| 验证项 | 方法 | 结果 |
|--------|------|------|
| 本地读无 TCP | 128.12 集群读期间 `ss -ltnp \| grep 5005` | **无任何 TCP 连接到 :5005x** → 本地实例读走 unix socket(共享内存) |
| 本地优先写 | 128.12 写入 30 key | 全落 n12-* 三盘（LOCAL），无跨节点 |
| 跨节点存在 | 128.11 读 128.12 写入的数据（cluster-check remoteHit） | remoteHit=300 → **走 TCP 跨节点读** |
| 跨节点 TCP 带宽 | 128.11 `-remote` 顺序读 300×4MiB（128.12） | 300 key/15.18s ≈ **80.9 MiB/s**（单连接 TCP，远低于本地 shm 并行） |

跨节点顺序单连接读取 ≈ 81 MiB/s，远低于本地 shm 并行读 13.6 GiB/s，印证"节点间通信存在且代价高"，集群主要依赖本地优先 + 共享内存命中。

## 4. 结论

1. **集群最大带宽**（三节点九盘，4MiB）：写汇聚 ≈ **19.7 GiB/s**，读汇聚 ≈ **36.4 GiB/s**；单机（三盘）写 ≈ 6.96 GiB/s、读 ≈ 13.6 GiB/s。
2. **同一节点内访问 = 共享内存（shmipc）+ 本地盘，零节点间通信**（ss 证明无 TCP）。
3. **跨节点访问 = TCP 网络**，仅发生在本地 miss 且由索引锚定到远端实例时。
4. 64 并发触发 shmipc 会话过载，建议压测/生产并发 <= 32/实例。

## 5. 遗留

- `taihu bench cluster` 集群读跨节点存在 miss（registry 定位边界），跨节点读写带宽建议用 `taihu-cluster-check`（已用于上述验证）补充；核心集群路由（注册/索引/本地shm/跨节点TCP）经 cluster-check 全链路验证通过。
