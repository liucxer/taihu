# taihu 六节点集群端到端读写性能测试报告（10.151.26.146-150,152 × 3 盘，18 实例，跨节点读篇）

日期：2026-09-11
部署二进制：`taihu server.50ebbe4` / `taihu bench cluster.50ebbe4`（commit `50ebbe4`，SDK 按 hostname 自动选路——同机 shm、跨节点 TCP），本地交叉编译 arm64 上传，18 实例全部重启为 HEAD 版本。

## 1. 测试目标

6 节点 × 3 盘位（18 实例）taihu 集群端到端读写性能，采集：
- 物理机 CPU（mpstat）、客户端/服务端进程 CPU（pidstat）
- 网络带宽（bond0.1326 数据面差分）
- 客户端与服务端 pprof（CPU 热点）
- 客户端带宽与延迟（bench 输出）

读性能测试**避开相同节点读**：读客户端与数据实例 hostname 错位，全部走 TCP 跨节点链路。

- **6 条跨节点链路全部同时达 110.4-111.4 MiB/s = 1Gbps 线速**（理论 125MB/s，实测净吞吐 111MiB/s≈89% 线速）

## 9. 结论

1. **写**：18 实例并行写聚合 **86.9 GiB/s**（每节点 14.2 GiB/s，3 盘 ≈ 4.7 GiB/s/盘），数据面 shm 本地，受磁盘写能力限制；客户端 CPU 主热点为普通 Put 的 memmove（可继续对接零拷贝写 API 消除）。
2. **跨节点读**：6 链路并行全部达 **1Gbps 线速 110-111 MiB/s**，聚合 665 MiB/s；路由完全正确（全跨节点、无同机读）。瓶颈为 bond0.1326 1Gbps 物理网络，非磁盘/CPU。
3. **零拷贝**：跨节点读 Take 命中 94.5-97.8%，客户端 memmove 从写路径 92.9% 降为读路径 0.71%——读路径零拷贝验证充分。
4. **资源占用轻**：物理机 CPU 17-27%，客户端读 <0.25 核，服务端几乎空闲。
5. 进一步提升跨节点读带宽需升级网络（1Gbps → 10Gbps+ bond 或改走高速互通网络）。
