| 函数 | flat% | 性质 |

## 七、结论（与读方向对比）

| 维度 | 4 客户端写 | 16 客户端读 |
|---|---|---|
| 带宽 | 2.47 GiB/s | 5.36 GiB/s |
| 瓶颈 | **磁盘（已满 2.5G 极限）** | **server CPU 拷贝（busy 69.6%）** |
| server CPU busy | 26.5% | 69.6% |
| server 内存操作 | ~35% | ~67% |
| server GC 开销 | ~15%（显著） | 可忽略 |
| 磁盘利用率 | 100% | ~80% |

1. **写方向是磁盘饱和型瓶颈**：4 客户端已打满单盘写极限（2.47G ≈ 2.5G），再增加客户端/连接也无法提升——多客户端写收敛测试（NC=4 即封顶）与此一致。
2. **写路径的 CPU 富余**（26.5%）说明写方向没有拷贝优化空间（瓶颈在盘上）；若后续上多盘（RAID/多设备），写路径的 GC 与 memmove 才会成为下一个瓶颈。
3. **读方向才是拷贝优化的主战场**（server memmove 48%）。

## 八、修正/说明

- 写延迟 p50≈100ms 与读 p50≈187ms 的差异：写满盘后写请求排队在磁盘队列，延迟反而更低是因为吞吐只有读的一半、队列深度小。
- 客户端 pprof 取样时间 25.34s 覆盖写测全程（写测约 25s，pprof 15s 居中）。
