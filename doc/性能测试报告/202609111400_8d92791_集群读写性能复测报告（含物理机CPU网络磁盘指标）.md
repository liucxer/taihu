## 3. 测试方法

三节点**并行**执行同一批压测（各自写/读本地盘）：

```bash
# 写（三节点并行，同时采集 CPU/磁盘/网络）
taihu bench cluster -mode write -node <N> \
  -tikv-pd 100.71.128.11:2379,100.71.128.12:2379,100.71.128.13:2379 \
  -size 4194304 -count 40000 -threads 32 -keys-prefix p4m-c1 -latency
# 读（同批 key）
taihu bench cluster -mode read -node <N> -tikv-pd ... -size 4194304 -count 40000 -threads 32 -keys-prefix p4m-c1 -latency
```

## 7. 瓶颈分层结论

| 层 | 实测值（/节点） | 是否瓶颈 |
|----|----------------|----------|
| 应用层（rpc-bench） | 写 7.3 / 读 16.9 GiB/s | — |
| 磁盘（iostat 实测） | 写 6.9-7.2 / 读 14.2-15.6 GiB/s | **是**（写打满、读接近极限） |
| 网络（物理网卡） | ≤2 Mbps | 否（shm 本地，几乎零网络） |
| CPU（mpstat） | 整机 ≤8-12%，单核 ≤22% | 否（96 核利用率极低） |

**结论**：集群读写带宽受**本地盘（NVMe）读写极限**约束，网络与 CPU 均非瓶颈；数据访问全部经共享内存命中本地盘，无节点间 TCP 数据面通信。

## 9. 读理论值验证（57 GiB/s 是否可达）

> 理论值：单盘读极限 6.5 GiB/s × 3 盘/节点 × 3 节点 ≈ **57 GiB/s**。

### 9.1 物理层验证：**可达，实测汇聚 ≈60 GiB/s**

在 128.11/12/13 各实例写入 shm-scan{1,2,3} 测试数据（每盘 12000×4MiB），逐盘独立 `-shm` 直连读（每盘 16 线程，打满单盘）：

| 节点 | DISK1 | DISK2 | DISK3 | 节点汇聚 |
|------|-------|-------|-------|----------|
| 128.11 | 6749.69 | 6733.54 | 6579.42 | **20062.65 MiB/s ≈19.6 GiB/s** |
| 128.12 | 6747.75 | 6781.19 | 6775.36 | **20304.30 MiB/s ≈19.8 GiB/s** |
| 128.13 | 6762.72 | 6751.12 | 6718.83 | **20232.67 MiB/s ≈19.8 GiB/s** |

- 单盘通过 shm 单会话 16 线程即打满 **6.6-6.8 GiB/s**（单盘读极限）；
- 三节点九盘汇聚 **≈60 GiB/s > 57 GiB/s 理论值**：物理层（盘 + shmipc + 客户端）完全支持，瓶颈不在硬件。

### 9.2 集群模式（rpccluster）瓶颈：当前 51 GiB/s，未达理论值

| 场景 | 结果 |
|------|------|
| 集群模式 32T（本轮主测） | 17.0 GiB/s/节点，汇聚 ≈51 GiB/s（每盘仅 5.7，未打满单盘 6.7） |
| 集群模式 48T / 64T | **失败**：`session is unhealthy`（shmipc 会话过载） |

**原因（代码层，非硬件）：**

1. **本地逐个试读放大**：rpccluster `Get` 对同 node 3 个实例**逐个试读**（[storage.go](file:///Users/liucx/gopath/src/github.com/liucxer/taihu/pkg/rpccluster/storage.go#L104-L128) `getFrom`），而写路径 picker 将 key 轮询分布到 3 实例 → 读时约 1/3 key 才命中第一个实例，平均 ~2 次 RPC/key，有效带宽被放大消耗（17/20 ≈ 0.85）；
2. **单 shm 会话**：`clientFor` 固定 `DialShm`（= DialShmPool(…,1)），每实例仅 1 会话；`-conns` 参数在集群模式**未传入** rpccluster（ClusterConfig 无 Conns 字段），无法借多会话提升并发；
3. **48+ 线程直接过载**：单会话 shmipc 并发承载有限，32 线程是稳定上限。

### 9.3 结论

- **57 GiB/s 理论值物理可达**（9.1 实测 60 GiB/s）；集群模式当前 51 GiB/s 的差距来自 rpccluster 读路径（试读放大 + 单 shm 会话），**优化方向**：
  1. `Get` 先按 RouteCache 定位写时锚定的实例（1 次 RPC 命中），消除逐个试读；
  2. `ClusterConfig` 增加 `Conns`，本地实例用 `DialShmPool(sessions)` 建多会话；
- 本轮按用户指示**仅记录结论、不改代码**，未实施上述优化。
