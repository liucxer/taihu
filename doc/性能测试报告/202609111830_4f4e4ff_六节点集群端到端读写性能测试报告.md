# taihu 六节点集群端到端读写性能测试报告（10.151.26.146-150,152 × 3 盘，18 实例）

日期：2026-09-11
基线 commit：`4f4e4ff`（客户端零拷贝写 API）+ `c9c08b6`（服务端写分段直写）+ `ae5d667`（server -listen 多 IP）
部署二进制（6 节点一致）：`taihu server.direct`（md5 39a01b46）/ `taihu bench cluster.direct`（md5 9d645c07），arm64

## 1. 测试目标

6 节点 × 3 盘位（18 实例）taihu 集群端到端读写性能，采集：
物理机 CPU（mpstat）、客户端/服务端进程 CPU（pidstat）、网络带宽（/proc/net/dev 差分）、
客户端与服务端 pprof、客户端带宽与延迟（bench 输出）。

## 7. 网络带宽

| 阶段 | 说明 |
|------|------|
| 写 | 数据面走 shm 本地；TiKV 索引 gRPC（跨网段 146→128）MB 级 |
| 读 | 大部分节点数据面 0；**146 有 ~75GB 跨节点流量**（bond1）——registry 冷启动时 picker 本地列表为空，部分 key 写跨节点（后续索引覆盖回本地，读时仍部分跨节点 → 146 读偏低 12.5 GiB/s） |

## 9. 瓶颈分析与结论

1. **写 85.3 GiB/s、读 93.0 GiB/s**（6 节点 × 3 盘），零拷贝 take 100%。
2. **盘能力远超 128 集群**：写 4.7 GiB/s/盘（128 为 2.5）、读 5.2 GiB/s/盘（128 为 5.8）——6 节点盘型号更快。
3. **CPU 成为吞吐相关因素**：写 busy 19-29%（客户端 memmove 7.5-10 核 + 服务端写处理 + 高带宽）、读 busy 17-28%（shmipc 高带宽处理）。**若接入集群零拷贝写（rpccluster 透传 NewPut），客户端 8-10 核 memmove 可消除**。
4. **146 异常**：registry 冷启动导致部分写跨节点（bond1 75GB），读偏低（12.5 vs 16.9 GiB/s）。**建议**：rpccluster registry 启动时同步预拉实例表，避免冷启动跨节点路由。
5. 数据面网络：同机 shm 零拷贝；跨网段仅 TiKV 元数据。
