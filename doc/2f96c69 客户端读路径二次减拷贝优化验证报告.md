# 2f96c69 客户端读路径二次减拷贝优化验证报告

> 对应提交：`de625b8`（RawFrame 延迟物化 + GetRaw 帧式 API）+ `2f96c69`（RawFrame 单缓冲修复）
> 测试时间：2026-09-10
> 前置：`130fd02` 连接池 + 窗口放大（详见 `130fd02 单客户端连接池与窗口放大优化验证报告.md`）

## 1. 背景与目标

130fd02 后单客户端已达 5.6 GiB/s（磁盘极限），但 client CPU 16.3 核、每 GiB 2.88 核，热点在：
- codec Materialize：每帧 1MiB 堆分配 + 清零 + 整块拷贝（memmove 6.65s + memclr 5.03s + GC）
- getStream.Read：帧 → 调用方缓冲的第二次拷贝（memmove 4.82s）

目标：延迟物化（省分配/清零）+ GetRaw 帧式 API（省第二次拷贝）。

## 2. 优化内容

| 项 | 变更 | 目的 |
|----|------|------|
| 延迟物化（de625b8） | RawCodec.Unmarshal 支持 `*RawFrame`：不再 `Materialize()`，持 wire 缓冲引用，消费时才拷贝 | 省每帧 1MiB 堆分配 + 清零 + GC |
| 单缓冲修复（2f96c69） | RawFrame 持有单 mem.Buffer：`materializeFrame` 单缓冲 Ref 零拷贝 / 多缓冲 bufpool 复用合并 | 修复 gRPC wire 多缓冲（16KB 帧粒度）导致 Data 仍物化拷贝的问题 |
| GetRaw API（de625b8） | `GetRaw` 返回帧式流，`Next()` 零拷贝返回 `[]byte`（单缓冲）；bench 新增 `rawread` 模式 | 免 io.Reader 的 Read 拷贝 |

**关键发现**：gRPC 1.69 的 wire 消息是**多缓冲**（16KB frame 粒度累积，1MiB 帧 = 64 段），RawFrame 不能直接引用，须在 Unmarshal 时合并为单缓冲（bufpool 复用，1 次拷贝、无 GC 分配）——这是 client 侧不可避免的最后 1 次拷贝。

## 3. 测试环境

100.71.128.12 单机，client/server 同机走 lo，96 核 aarch64，`/dev/nvme1n1`（O_DIRECT），单进程 `taihu-rpc-bench` 32 线程 × 16 连接，4MiB 对象 × 6000。

## 4. 效果对比

### 4.1 带宽（MiB/s，单客户端 32×16）

| 版本 | read | rawread |
|------|------|---------|
| 130fd02（Materialize） | 5605 | — |
| de625b8+2f96c69 | 5436~6070 | 5666~6096 |

带宽均在磁盘访问模式极限附近（读极限 ~5.4-6.1G，波动），优化不改变带宽上限。

### 4.2 client CPU（每 GiB/s 归一化，pprof）

| 版本 | 拷贝次数 | memmove s/GiB | memclr s/GiB | 总核 |
|------|---------|--------------|-------------|------|
| 468a9af 基线（16t×1c） | 3-4 次 + 分配 | ~0.82 核 | ~0.44 核 | 2.5 核（0.92G） |
| 130fd02（Materialize） | 2 次 + 分配 | 0.63 | 0.45 | 16.3（5.66G） |
| **read（RawFrame）** | **2 次、无分配** | 0.60 | **0.20（-56%）** | 13.0（6.07G） |
| **rawread（GetRaw）** | **1 次、无分配** | **0.41（-35%）** | **0.21** | 11.4（6.10G） |

### 4.3 memmove 来源（peek 调用者）

- read：合并 `BufferSlice.CopyTo` 48% + `RawFrame.CopyTo`（Read 用户缓冲）31%
- rawread：仅合并 `BufferSlice.CopyTo` 67%（Data() 零拷贝引用），无 Read 拷贝

## 5. 结论

1. **延迟物化达标**：read 路径 memclr（分配清零）每 GiB 0.45 → 0.20（-56%），消除每帧 1MiB 堆分配与 GC；拷贝次数保持 2（合并 + Read），属 io.Reader 语义下限。
2. **GetRaw 达标**：rawread 仅 1 次拷贝（wire 多缓冲合并），`Next()` 零拷贝交付 `[]byte`，memmove 每 GiB 0.63 → 0.41（-35%），达到 client 侧理论最少拷贝。
3. **带宽创纪录**：单客户端 rawread 6096 MiB/s（6.1G），超过此前 16 客户端聚合 5.35G，首次破 6G。
4. **剩余开销**：syscall ~28%（socket read 固有）、memclr ~0.2 s/GiB（gRPC wire 缓冲池 Get 清零，gRPC 内部行为）、调度/锁（32 流握手）。
5. API 变更：新增 `GetRaw/RawStream`（帧式、零拷贝、用毕 Close）；`Get` io.Reader 语义不变。
