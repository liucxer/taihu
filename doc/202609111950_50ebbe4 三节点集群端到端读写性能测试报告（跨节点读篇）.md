# taihu 三节点集群端到端读写性能测试报告（跨节点读篇）

日期：2026-09-11
基线：`50ebbe4`（SDK 按 hostname 自动选路——同机走 shm、跨节点走 TCP）
部署：三节点 × 3 盘位（9 实例：`n11-nvme1/2/3`、`n12-nvme1/2/3`、`n13-nvme1/2/3`），二进制 `/tmp/taihu-server.new`、`/tmp/taihu-rpc-bench.new`，arm64

## 0. 结论先行

- **写（同机 shm）**：三节点聚合 **~21.6 GiB/s**（每节点 ~7.38 GiB/s / 3 盘 ≈ 2.46 GiB/s/盘，写命中盘写极限）。
- **跨节点读（TCP）**：每方向 **~107–112 MiB/s**（1 Gbps 网卡饱和），聚合三条方向 **~331 MiB/s**。
- **根本瓶颈**：数据面 `bond0` = **1000Mb/s（1Gbps）**。跨节点读完全被 1Gbps 网卡钉死；两端进程 CPU 几乎为 0（<1 核、物理机 <1.4%），pprof 两端均 ~66–72% `syscall.Syscall6` 等待。
- 同机 loopback 读为 ~17 Gbps，跨节点只有 1Gbps → **跨节点比同机约慢 150 倍**，是测试网卡环境瓶颈，非软件缺陷。

## 1. 测试目标

三节点 × 3 盘位集群端到端写/读性能，采集：物理机 CPU（mpstat）、客户端/服务端进程 CPU、网络带宽（/proc/net/dev 差分）、客户端与服务端 pprof、客户端带宽与延迟。**读性能避开同节点，强制 hostname 错位走 TCP**。

## 2. 测试环境

| 项 | 值 |
|----|----|
| 节点 | 100.71.128.11（XCKP04）/ 128.12（XCKP05）/ 128.13（XCKP06），96 核 aarch64 |
| 实例 | 每节点 3 × taihu-server，共 9 实例；TCP RPC :50000/50002/50004 |

| 数据面网卡 | **bond0（VLAN bond0.1253）= 1000Mb/s** |
| 对象 | 写：4MiB × 60000/节点（前缀 p4m-wa/wb/wc）；读：同批前缀 × 4000/腿 |
| 压测 | taihu-rpc-bench 集群模式（-client-name + -tikv-pd），客户端放各节点本机 |

## 3. 关键修因：时钟偏差导致跨节点实例被判离线

初测跨节点读全部 `run error: file does not exist`。定位到：

- 客户端 `Storage.Get` 先 `lookup`（路由缓存 → TiKV 索引 → 实例名 → registry 解析）。
- registry `buildSnapshot` 按 `LastHeartbeat` 超时（5s）**过滤掉心跳过期的实例**。
- 写/本机读均走同机 shm，hostname 一致即可，从不依赖远端实例解析 → 未暴露。
- 排查发现 **128.12/128.13 系统时钟比 128.11 慢 14–15 分钟**（NTP 未同步）：server 心跳 `LastHeartbeat` 用节点本地时间写入，128.11 客户端按自身时钟判定 `n12-* / n13-*` 全部超时 → 从 registry 剔除 → 跨节点 `Lookup` 失败 → 回源（Source=os.ErrNotExist）→ "file does not exist"。
- 修复：`date -s` 将 128.12/128.13 对齐 128.11，1s 后心跳刷新，9 实例全部 `online`，跨节点读恢复。

> 教训：三节点集群测试必须先校验节点时钟一致，否则跨节点寻址按心跳超时被静默剔除。

| **聚合** | | **5528.61** | **22114.42（≈21.6 GiB/s）** | | | |

写资源画像（pprof + mpstat）：

- 客户端：**84.8% `runtime.memmove`**（~2 核，66.08s/32.66s = 202%），即同机 shm 写路径 payload 拷贝；`frame stats`：write 收帧 0。
- 服务端：54.6% `syscall.Syscall6`（磁盘 O_DIRECT 写），占空 ~25%（6.54s/26.17s）。
- 物理机 CPU：avg 4.1–5.3% all-cores，峰值 <6.7% → 写瓶颈在**单盘写极限**（2.46 GiB/s/盘），CPU/网络均非瓶颈。

## 5. 跨节点读性能（环形 TCP，规避同机，4MiB×4000/腿，32 线程）

读环形：A=129.11 读 128.13 数据（p4m-wc）；B=128.12 读 128.11（p4m-wa）；C=128.13 读 128.12（p4m-wb）。两端 hostname 错位 → 强制走 TCP。

| 方向 | 数据源 | ops/s | MiB/s | p50 | p90 | p99 | take/copy | 数据端 TX 实测 |
|------|--------|-------|-------|-----|-----|-----|-----------|----------------|
| A | 13→11 | 27.97 | 111.89 | 1045ms | 2190ms | 2883ms | 3675/325 | 16.6GB/143s≈**117MB/s** |
| B | 11→12 | 27.96 | 111.84 | 965ms | 2311ms | 2791ms | — | 16.6GB/143s≈**117MB/s** |
| C | 12→13 | 26.80 | 107.21 | 923ms | 2403ms | 3801ms | — | 17.3GB/149s≈**117MB/s** |
| **聚合** | | | **~331 MiB/s** | | | | | |

> 注：跨节点读同腿在 128.x 网段走同一个 1Gbps 链路，每方向独立饱和 1Gbps（≈119 MiB/s 上限），实测 107–112 MiB/s 为满速。两端均 0 error、take 命中 91.9%（legA copy 325/4000）。

读资源画像：

- 物理机 CPU：avg **0.6–1.4%** all-cores，峰值 <3.8%（96 核）；数据端 0.62–1.34%、读者端 0.77–1.39%。
- 客户端进程：avg 15–31%（<1 核）。
- 数据端 server 进程：每实例 avg 0.8–1.3%。
- 客户端 pprof（legA）：**66% `syscall.Syscall6`**（TCP 读写 syscall）+ 6.6% futex → 网络 I/O 等待。
- 数据端 server pprof：**72% `syscall.Syscall6`**，整窗采样 430ms/26s = **1.65%** → 纯网络+磁盘等待。
- 结论：跨节点读**完全 1Gbps 网卡饱和，CPU/磁盘近乎空闲**，瓶颈在 NIC。

## 6. 分析

1. 写为**同机 shm**：不占网络，字节打到本机 NVMe，7.38 GiB/s/节点受单盘写极限约束；客户端 memmove（shm 拷贝）+ server 磁盘 syscall 为主，物理机 CPU 低。
2. 跨节点读为 **TCP**：被测数据面 100.71.128.x 仅 `bond0 = 1000Mb/s`，单方向极限 ≈119 MiB/s。实测 107–112 MiB/s（94–98% 线速）即是满速。延迟 p50≈1s 是在 32 线程全部并发、链路被 28 个流瓜分下的排队时延，属网络饱和预期。
3. **网络带宽噪声**：`/proc/net/dev` 差分三方交叉确认（客户端带宽 111.89 MiB/s ≈ 数据端 TX 117 MB/s ≈ 1Gbps）。
4. 数据面 1Gbps 是测试集群能力上限；若需更高跨节点吞吐，须上 10Gbps 及以上网络。

## 7. 结论

1. 三节点×3 盘集群端到端：写 **21.6 GiB/s**（同机 shm，单盘写极限）；跨节点读 **107–112 MiB/s/方向**（1Gbps 网卡饱和）。
2. 跨节点读两端 CPU <1 核、物理机 <1.4%，pprof 均 syscall 等待——**纯网络（NIC）瓶颈**，sdk 零拷贝 take 命中 ~92% 仍生效。
3. 节点时钟偏差会静默剔除跨节点实例导致寻址失败，须先对齐时钟。
4. 跨节点与同机的巨大差异（1Gbps vs 17Gbps loopback，~150×）源于数据面网卡，非软件瓶颈。

## 8. 测试还原

```bash
# 1) 对齐时钟（关键，先做）
date -s @$(ssh 128.11 'date +%s')   # 在 128.12 / 128.13 各执行一次

# 2) 写（三节点并行，独立前缀，客户端本机走 shm）
taihu-rpc-bench -mode write -client-name t11w -tikv-pd 100.71.128.11:2379,... \
  -size 4194304 -count 60000 -threads 32 -keys-prefix p4m-wa -report-interval 5s -latency -cpuprofile w.cpu

# 3) 跨节点读（hostname 错位强制 TCP；此例 128.11 本机读 128.13 的 p4m-wc）
taihu-rpc-bench -mode read -client-name cr11 -tikv-pd ... -size 4194304 \
  -count 4000 -threads 32 -keys-prefix p4m-wc -latency -preload -cpuprofile r.cpu

# 4) 采集
mpstat -P ALL 1 &  pidstat 1 &  /proc/net/dev 差分(bond0.1253) &  双端 :50001 pprof=26s
```

> 采样脚本：`dist/build/test_read.sh`（读者端）+ `dist/build/sample_data_node.sh`（数据端），已部署各节点 `/tmp/`。
