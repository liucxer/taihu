# c871421 RPC 端到端读写性能测试报告

> 对应提交：c871421（feat: 实现设计文档_v3 gRPC 远程访问层（server/client/rpc-bench））

## 1. 测试目标

验证 taihu 远程访问层（gRPC）端到端读写性能与资源占用：
- 端到端写/读带宽、吞吐、延迟；
- 物理机 CPU（整机均值 + 逐核 + TOP 忙核）、磁盘（iostat 实测）占用，判断瓶颈所在；
- 测试程序（rpcclient/Storage 路径）CPU pprof 热点，重点确认数据拷贝开销（呼应「减少拷贝」优化动机）。

当前被测代码为**未做接口改造的基线**（`ObjectStore` 为 io.Reader/io.ReadCloser 流式接口），供后续 `[]byte` 改造作为对比基准。

## 2. 测试环境

| 项 | 值 |
|---|---|
| 服务器 | 100.71.128.12（与 client 同机） |
| 架构 / CPU | aarch64，96 核 |
| 系统 | Linux 4.19.90 bclinux |
| 编译产物 | `/tmp/taihu-server.new`、`/tmp/taihu-rpc-bench.new`（go1.24，GOTOOLCHAIN=auto 自动补齐 go1.25.0） |
| 数据设备 | `/dev/nvme1n1`（1.8T 裸盘，O_DIRECT） |
| 元数据 | `/tmp/tdb-rpc`（pebble，同一 server 实例内复用） |
| 对象大小 | 4MiB（4194304 B） |
| 网络 | client/server 同机，走 loopback（`100.71.128.12` 路由至 lo）；bond0.1253 网卡计数测试期间几乎不变 → 网络非瓶颈 |
| 部署方式 | `taihu-server -addr :50051`；`taihu-rpc-bench -addr 100.71.128.12:50051` |

## 3. 测试方法

两端同机，`taihu-rpc-bench` 作为 client 连 server（回环）。先 `-mode write` 写入 `count` 个不同 key，再 `-mode read` 读同一批 key（每 key 只读一次）。

- 写测：`-mode write -size 4194304 -count 10000 -threads 16 -keys-prefix 4m-rpc-f -latency`
- 读测：`-mode read -size 4194304 -count 10000 -threads 16 -keys-prefix 4m-rpc-f -latency`
- 数据量：单轮 10000×4MiB = 40GB
- 采集：写/读期间后台 `iostat -d /dev/nvme1n1 1` + `mpstat -P ALL 1`（同一命令内起停，贯穿全程）；独立跑一次读测带 `-cpuprofile` 采集程序热点

注：server 端 Storage 未做 `LoadCache` 预热，读路径含真实 pebble 元数据查询，反映端到端真实路径。

## 4. 测试结果

### 4.1 带宽与吞吐（16 线程、4MiB 对象）

| 模式 | 轮次 | 对象数 | 数据量 | 耗时 | 吞吐 ops/s | 带宽 MiB/s |
|---|---|---|---|---|---|---|
| 写 | 第 2 轮（复采） | 10000 | 40GB | 44.08s | 226.87 | **907.48** |
| 读 | 第 2 轮（复采） | 10000 | 40GB | 43.50s | 229.91 | **919.64** |

（首轮：写 901.30 / 读 947.22 MiB/s，因采样器调度略有波动，以复采稳定值为主。）

### 4.2 延迟（16 线程，`-latency`）

| 模式 | p50 | p90 | p99 |
|---|---|---|---|
| 写 | 70.33ms | 76.02ms | 83.09ms |
| 读 | 67.17ms | 80.31ms | 90.77ms |

延迟明显高于本地直连（本地应为亚毫秒级），说明单 stream 端到端每 op 处理开销较大。

## 5. 资源占用

### 5.1 CPU（mpstat -P ALL 逐秒均值）

| 模式 | 整机 busy | usr | sys | iowait | idle | 结论 |
|---|---|---|---|---|---|---|
| 写 | 10.5% | 4.1% | 1.5% | 4.4% | 89.5% | **非 CPU 瓶颈** |
| 读 | 6.3% | 4.2% | 1.6% | 0.2% | 93.7% | **非 CPU 瓶颈** |

TOP 忙核（含 iowait 分解，均不高）：

- 写：core0 13.9%（usr7.0）、core19 13.1%、core6 12.9%、core65 12.8%、core66 12.4%
- 读：core22 13.6%（usr8.7）、core0 13.3%、core49 12.9%、core1 12.7%、core18 12.3%

96 核中单核 busy 最高仅 ~14%，整机极度空闲。

### 5.2 磁盘（iostat 实测，稳态帧，剔除首帧累计与空闲）

| 模式 | 稳态帧数 | 平均带宽 MiB/s | 峰值 MiB/s |
|---|---|---|---|
| 写（kB_wrtn/s） | 44 | **906.8** | 983.9 |
| 读（kB_read/s） | 43 | **920.2** | 1024.0 |

写磁盘实测带宽与 rpc-bench 上报带宽一致（907 ≈ 907），交叉验证有效。峰值约 1GiB/s，**低于 NVMe 裸盘理论上限，磁盘非瓶颈**。

### 5.3 网络

client/server 同机，回环通信，bond0.1253 网卡计数在测试期间几乎不变（流量走 lo）→ 网络非瓶颈，本文不量化网卡带宽。（多节点端到端需另测，本机无法反映真实网卡瓶颈。）

## 6. 瓶颈分析与 pprof 热点

读路径 CPU profile（`go tool pprof`, Duration 22.11s, 283% 采样）：

| 名 | flat% | cum% | 说明 |
|---|---|---|---|
| `internal/runtime/syscall.Syscall6` | 22.73% | 22.73% | O_DIRECT read/write 系统调用 |
| `runtime.memmove` | 17.16% | 17.16% | **数据拷贝搬运** |
| `runtime.memclrNoHeapPointers` | 16.35% | 16.35% | **内存清零（大缓冲分配/复用）** |
| `runtime.stealWork` | 3.45% | 10.07% | 调度器窃取工作 |
| `internal/runtime/atomic.Uint8.Load` | 2.86% | 2.86% | 原语（inline） |

- **memmove(17%) + memclr(16%) 合计约 33%** 消耗在内存搬运与清零：来自远程读路径的 io.Pipe 双拷贝、每 RPC/O_DIRECT 对齐缓冲的分配与清零。
- 系统调用 22.7%：225 ops/s × 每 op 的 O_DIRECT IO + gRPC socket 系统调用。
- 磁盘实测峰值 ~1GiB/s 而 CPU 空闲 >89%，**端到端瓶颈在用户态数据拷贝与系统调用开销，而非磁盘或 CPU 满负荷**。

## 7. 结论与建议

1. c871421 端到端写 907 MiB/s / 读 920 MiB/s（16 线程 4MiB），写/读延迟 p99 ≈ 83 / 91ms，功能与链路正常。
2. 磁盘峰值 ~1GiB/s、CPU idle >89%，均非瓶颈；瓶颈集中在**数据搬运（memmove）+ 缓冲清零（memclr）+ 系统调用**三项用户态/IO 开销。
3. 与「减少拷贝」目标是**强相关**：pprof 实证 memmove+memclr 占读路径 CPU 约 33%。优化优先级：
   - 去掉 `rpcclient.Get` 的 io.Pipe 双拷贝（改边 Recv 边写入/或分块直接交付）；
   - 对齐缓冲复用化/消除每 op 大块清零（bufpool 若遇分配会由运行时清零，命中率高则免）；
   - 批量/更大分块降低每字节系统调用频次。
4. 该报告作为**接口改造前的基线**；`[]byte` 改造后应复测并对比本报告的带宽/延迟与 pprof memmove/memclr 占比。
