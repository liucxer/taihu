# 客户端共享内存零拷贝写 API（消除写路径客户端 memmove 84.62%）

## Context

**问题**：写路径客户端 `runtime.memmove` 占 84.62% CPU（三节点集群实测）——[shmWriteFrame](file:///Users/liucx/gopath/src/github.com/liucxer/taihu/internal/transport/shmipc_server.go#L105) 的 `copy(buf[payloadOff:], payload)` 把应用数据从用户缓冲拷贝进共享内存。

**目标**：新增客户端零拷贝写 API `PutWriter.Reserve(n)`——返回共享内存数据区**直接引用**（4K 对齐，探索确认 buffer_manager.go L366-368），应用层直接在共享内存中生成/写入数据，免掉 memcpy。写带宽受单盘极限不变，收益=客户端 CPU 释放（187-225% → 显著下降）。

**关键前提（探索确认）**：
- `linkedBuffer.Reserve` 返回 buf 是共享内存 data 区引用（buffer.go L175-214），数据帧 payload 起点 `buf[4096:]` 4K 对齐（shmWriteFrame L101-104）
- Reserve 后到 Flush 前有效（Flush 内 done/clean 才更新切片，stream.go L209-210），调用方必须在其间完成写入
- **协议不变**：仍发 opPutHeader/opPutData/opPutEnd（服务端 handleShmPut 已逐帧 PutAppend 直写，c9c08b6，无需改动）；opPutData 带 pad 布局已具备（客户端数据区天然 4K 对齐）
- 需处理分块边界（chunkSize 4MiB）与单切片容量（shmSliceSize），对调用方透明封装

## 改动清单

### 1. transport.ShmConn 拆帧 API（shmipc_client.go / shmipc_server.go 共用帧函数）

新增（复用 shmWriteFrame 的布局逻辑，拆为 reserve+commit 两步，消除 copy）：

```go
// shmReserveData 预留一帧数据区（含 pad），返回 payload 直接引用（4K 对齐，零拷贝）。
// 返回后调用方须在 Flush 前完成写入，然后调用 shmCommitFrame。
func shmReserveData(st *shmipc.Stream, op OpCode, size int) ([]byte, error)
// shmCommitFrame 写帧头 [4B len][1B op] 并 Flush（数据已在 reserve 区，不再 copy）。
func shmCommitFrame(st *shmipc.Stream, op OpCode, size int) error
```

- `shmReserveData`：`buf, err := st.BufferWriter().Reserve(shmDataPad+size)`，返回 `buf[shmDataPad:shmDataPad+size]`
- `shmCommitFrame`：写 `buf[0:4]`=len、`buf[4]`=op（buf 是 sendBuf 首个切片，需从 Reserve 返回值反推或由调用方持有头引用；实现上用 Reserve 返回 buf 的 `[:5]` 部分，commit 时写入）+ `Flush`；同步累加 statTx* 统计（与 shmWriteFrame 对齐）

### 2. transport.ShmConn 零拷贝写流（shmipc_client.go）

```go
// shmPutWriter 共享内存零拷贝写流（一个对象一个，持有流与逐帧状态）。
type shmPutWriter struct {
    c   *ShmConn
    st  *shmipc.Stream
    size, written int64
    cur []byte  // 当前帧数据区（Reserve 返回，含头部引用）
    err error
}
// PutBegin 开始写对象：GetStream + 发 opPutHeader（控制帧，shmWriteFrame）。
func (c *ShmConn) PutBegin(ctx context.Context, key string, size int64) (*shmPutWriter, error)
// Reserve 返回 n 字节共享内存可写区（零拷贝直写）；当前帧剩余不足自动切帧。
func (w *shmPutWriter) Reserve(n int) ([]byte, error)
// Write 拷贝写（通用语义，内部调 Reserve + copy）。
func (w *shmPutWriter) Write(p []byte) (int, error)
// Commit 结束：flush 末帧 + 发 opPutEnd + 读 opResp + PutBack。
func (w *shmPutWriter) Commit() error
```

- 切帧逻辑：`written % chunkSize + n > chunkSize` 时先 `shmCommitFrame(st, opPutData, 当前帧长度)` 再 `shmReserveData`
- 每帧 payload ≤ chunkSize（4MiB），单切片容纳（shmSliceSize=4MiB+8K）
- 错误处理：任何失败记录 w.err，Commit 返回并 PutBack 流

### 3. rpcclient.Storage 新方法（storage_rpc.go）

```go
// PutWriter 共享内存零拷贝写（仅 shm 连接支持；TCP 返回 ErrShmOnly）。
type PutWriter struct{ w *transport.ShmPutWriter }  // 或直接包装
func (s *Storage) NewPut(ctx context.Context, key string, size int64) (*PutWriter, error)
func (w *PutWriter) Reserve(n int) ([]byte, error)
func (w *PutWriter) Commit() error
```
- 断言 `s.conns[0]` 为 `*transport.ShmConn`（shm 连接池单连接多会话），否则返回不支持错误

### 4. 压测工具（taihu-shm-bench / taihu bench cluster）

- runWorker write 分支：尝试 `NewPut`（类型断言），成功则 `Reserve(size)` 直接在共享内存生成 payload（`buf[j]=byte(j&0xff)`）→ `Commit`；失败回退 `s.Put`
- 新增 `-zero-copy-write` 标志（默认开）便于对比

## 验证

1. **本地**：`go build ./...` + `go vet ./...`。
2. **正确性**（128.13 单实例，shm-bench）：零拷贝写 → `-verify-content` 读校验（4MiB 整帧 / 尾帧 4MiB+1 / 多帧 8MiB+1 / 空对象）。
3. **性能**：客户端写 pprof——`runtime.memmove` 84.62% → ~0；写带宽不变（单盘极限 2.5 GiB/s）。
4. **回归**：普通 `Put` 路径不受影响（服务端协议未变）；集群读不受影响。
5. 可选：三节点集群写复测（客户端 CPU 释放效果）。

## 备注

- 帧协议、服务端（handleShmPut 分段直写）、网络格式均不变，两端二进制须同版本（客户端新 API 仅客户端侧变化，服务端兼容）。
- Reserve 返回的共享内存区写入后由 Commit 的 Flush 对端可见；调用方不得跨 Commit 持有引用。
- 若后续需要"多缓冲/预取写"可在 PutWriter 上扩展（当前一次一个对象）。
