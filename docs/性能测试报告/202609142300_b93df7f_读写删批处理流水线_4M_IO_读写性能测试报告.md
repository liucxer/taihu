## 3. 测试方法

fio 4M 顺序 IO（libaio，direct=1，bs=4M），4 卷并发，每卷一个 fio 进程，`group_reporting=1`。预创建文件规避 FUSE 并发布局挂起（`fallocate`）。全轮并行采集：

- 整机 CPU：`mpstat -P ALL 1s`
- 网络：`sar -n DEV 1s`
- 磁盘：`iostat -x 1s`（nvme1n1/2n1/3n1）
- 进程 CPU：`pidstat -u -p <pid> 1s`（客户端 4 进程 + 服务端 3 进程）
- pprof：测试中段 `curl .../pprof/profile?seconds=N`（客户端 6066 + 服务端 50001/50004/50005）

**参数矩阵**（perf_pipe 轮，一轮内先写后读）：

| 轮次 | numjobs/卷 | iodepth | 数据规模/卷 |
|------|-----------|---------|------------|
| j4_d8  | 4 | 8 | 1GiB×4 |
| j8_d16 | 8 | 16 | 1GiB×8 |
| j16_d16 | 16 | 16 | 1GiB×16 |
| j16_d32 | 16 | 32 | 1GiB×16（read 侧复用写文件） |
| j32_d16 | 32 | 16 | 1GiB×32 |

## 10. 结论

1. **最佳配置**：写 32 jobs × iodepth 16 → **6.6~6.9 GiB/s**（磁盘稳态聚合 6678 MiB/s 打满，util ~87%）；读 16 jobs × iodepth 32 → **18.9 GiB/s**（磁盘稳态聚合 19505 MiB/s / 峰值 20113 MiB/s / util 100%）。
2. **应用与磁盘吻合**：写 101.6%、读 99.3%（写侧 fio 均值窗口即时带宽偏高、读侧 iostat 秒级稳态即时带宽偏高，均在窗口边界抖动范围内），磁盘为物理瓶颈，链路无额外损耗。
3. **批处理流水线价值**：写路径服务端 CPU 仅 ~2.1 核（48~54% io_submit syscall），规模化下批量提交避免逐帧开销；读路径服务端近乎空闲（9% 采样窗口）。批量实现（aio SubmitWriteBatch / device AppendBatch / storage BatchPutCommit / BatchDelete / 写删 batchWriter/deleter 流水线）在 4M IO 压测下稳定正确运行（writeBatches 持续递增、0 崩溃）。
4. **CPU 分布**：写=客户端 memmove+syscall 主导（合计 ~56 核，非瓶颈，磁盘先饱和）；读=客户端 syscall+go-fuse 协议（~8 核）+ 服务端近零。
5. **延迟**：写 4M IO clat p50≈1.1ms / p99≈1.2ms；读 p50≈0.37ms / p99≈0.48ms（排队深度已饱和下的端到端延迟）。
6. 128 集群三节点旧 taihu 已全部关闭，128.13 为当前唯一 taihu 服务节点（3 server + 4 挂载客户端），性能测试与历史单机基线（~6.4/18 G) 一致并有小幅提升。
