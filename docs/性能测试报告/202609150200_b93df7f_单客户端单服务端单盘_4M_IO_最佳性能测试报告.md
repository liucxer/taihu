## 1. 测试目标

1. 在**单个客户端 + 单个服务端 + 单块裸盘**的最简拓扑下，用 `taihu bench single`（shm 共享内存传输）测 4 MiB IO 读写的最佳带宽与延迟，扫描线程数 / conns / pipeline 参数。

## 7. 关键发现

1. **`--batch 32 --batch-workers 8` 参数导致 bench single shm 读路径卡死**：开启批读参数后，读在数千次请求（16045/20000 或更早 5/20000）后停滞为 0 ops/s，server 空闲、磁盘 idle（请求未下发）；去掉该参数后读稳定直上 6400 MiB/s。生产路径（FUSE/nefs.client）不受影响，仅 `bench single` shm 直连触发，疑似批读 worker 死锁，待后续排查。
2. **pipeline≥2 / 高并发读尾段卡顿**：64t pipeline=4 在 19944/20000 尾段卡死；读建议 pipeline=1。
3. **kill -9 重启 server 会丢尾部对象**：灌写 40000 对象后经多次 kill -9 重启，count=40000 读出现 `key not found`（仅 ~20000+ 对象存活），读测试改用 count=20000 规避；后续测试注意优雅停机（kill -TERM）。

## 10. 结论

1. **单客户端+单服务端+单盘 4M 最佳性能**：读 **6400.87 MiB/s**（16t/c8/p1，p50 9.4ms），写 **2550.88 MiB/s**（8t/c8/p1，p50 12.3ms）。
2. **磁盘为读写共同瓶颈**：读磁盘稳态 6776 MiB/s / util 100% / 峰值 6812；写磁盘稳态 2547 MiB/s / util 100% / 峰值 2582。应用与磁盘稳态一致（写 100.1%，读稳态区间速率吻合），无链路损耗。
3. **读参数规律**：低线程（8~16）最优，conns 无影响，pipeline=1 必须；读瓶颈在磁盘，shm 通道在 16 线程内不构成瓶颈。
4. **批读参数（--batch）在本拓扑下有卡死缺陷**，需排查修复；不使用批读时单盘读性能较历史提升 +2.3%。
